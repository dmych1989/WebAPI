- 异常时回滚状态标记

## 修复刷新按钮自动刷新不停问题

### 问题根因
`setInterval(refreshAll, 15000)` 每 15 秒触发完整健康检查（含 `checkChannels()`），
健康检查本身耗时 15-45 秒（6 个渠道逐个检测），导致上次未完成就触发下次，形成堆积循环。

### 修复方案
- `refreshAll(forceCheck)` 改为双模式：
  - 手动点击：`refreshAll(true)` → 完整渠道健康检查
  - 自动定时：`refreshAll(false)` → 只读缓存状态（`loadProviders()`），不触发健康检查
- 新增 `_refreshBusy` 标志位防连点
- 自动刷新间隔从 15s 延长到 30s
- 新增 `loadChannelSummary()` 为轻量刷新补充状态栏汇总

## 修复浏览器自动关闭（未登录就报"提取成功"）

### 问题根因
三处 Bug 叠加导致：
1. **误判已登录**：`_wait_and_extract()` 检查 URL 是否含 `/chat/`，
   但豆包/元宝的 `login_url` 本身就含 `/chat/`，导致页面刚加载就被判定为"已登录"
2. **未登录就提取**：提取器在 `login_detected=False` 时仍每 2s 执行一次，
   `all_cookies` 永远返回非空（含会话 Cookie），导致立即返回
3. **Cookie 长度不校验**：5 字符的会话 Cookie 也当作有效凭证保存

### 修复
- 登录检测改为：`current_url != login_url && current_url != start_url && 含关键词`
- 提取逻辑加 guard：`if not login_detected: continue`
- Cookie 最小长度检查：cookie ≥ 80 字符，token ≥ 20 字符

## 复刻 Chat2API 凭证提取逻辑

### Chat2API 核心机制
1. **onBeforeSendHeaders** — 拦截所有出站请求, 实时捕获 Authorization header
2. **onHeadersReceived** — 拦截 Set-Cookie 响应头  
3. **cookies.on('changed')** — 监听 Cookie 变化事件
4. **isValidToken()** — JWT/JWE 解析 + guest 账号拒绝 + 多级长度阈值
5. **Token 验证后提交** — 提取到 Token 后必须通过 API 调用验证才返回

### WebAPI 复刻（Playwright 适配）
- `page.route("**/*")` → 拦截所有请求的 Authorization header
- `page.on("response")` → 捕获 Set-Cookie
- 轮询 localStorage + cookies 每 2s（替代 cookie changed 事件）
- `_is_valid_token()` — 完整复刻 Chat2API 的 JWT/JWE/Base64/通用 Token 检测
- `_validate_extracted_value()` — 实际 API 调用验证凭证
- MiniMax: `localStorage._token` + `user_detail_agent` (与 Chat2API 一致)
